## Summary

- release type: `0.x patch release`
- runtime version: `0.1.2`
- release date: 2026-03-18

Vilano Runtime `0.1.2` is a patch release focused on day-to-day developer experience: project-local
runtime configuration, better operator visibility for runs and services, and safer child workflow
spawning defaults.

## Compatibility

- protocol version: `1`
- schema version: `13`
- support scope: local-first, single-machine, Bun-first

## Highlights

- Projects can now define shared runtime defaults in `vilano.toml`, including kernel port,
  execution home, managed worker settings, repo pool size, and `.env` file loading.
- `vilano run explain <run-id>` adds a faster operator path for answering what a run is doing,
  what it is waiting on, and which child work is still active.
- `vilano run explain --json` exposes the same explanation surface as structured output for tooling.
- `vilano service history <service> --service-key <key>` replays the durable timeline for a keyed
  service instance without requiring operators to find the raw run id first.
- `run inspect` now includes the explain summary directly, so the default inspect path is more
  useful under pressure.
- `ctx.spawn(..., { policy: "fresh" })` adds an explicit way to avoid accidental child-run reuse
  from coarse keys while preserving the existing by-key reuse behavior.

## Notes

- `vilano.toml` intentionally does not control the install/update release channel.
- Global commands such as `vilano help`, `vilano version`, `vilano update`, `vilano rollback`, and
  `vilano doctor` now skip project config loading so repo-local mistakes do not break machine-level
  operations.

## Upgrade

```bash
vilano update
vilano version
```
