## Summary

- release type: `0.x patch release`
- runtime version: `0.1.3`
- release date: 2026-03-28

Vilano Runtime `0.1.3` is a patch release focused on runtime hardening, recovery tooling, and
codebase cleanup ahead of broader `0.2` surface work.

## Compatibility

- protocol version: `1`
- schema version: `13`
- support scope: local-first, single-machine, Bun-first

## Highlights

- Per-activation `--once` workers now exit explicitly after finishing their activation, which
  prevents lingering event-loop handles from stalling later leases.
- Local SQLite handling is more resilient under burst contention, with broader busy-retry coverage,
  lower fence/write pressure, and richer runtime diagnostics for operator debugging.
- `vilano project purge-runtime <project>` adds a project-scoped recovery path for clearing stuck
  runs and service state without wiping the full runtime environment.
- The runtime debug surface now reports queue heads, pending backlog by project, active lease state,
  and recent busy-retry exhaustion so queue wedges are easier to inspect.
- CI bootstrap is more robust on scheduled macOS runs because Mix/Hex dependency setup now retries
  instead of failing immediately on transient registry fetch problems.

## Internal Maintainability

- Managed worker launch, activation session setup, storage helpers, daemon client APIs, CLI command
  handlers, CLI output renderers, and public router handlers were split into smaller modules.
- These refactors do not change the public runtime protocol, but they reduce boundary sprawl and
  make the next round of runtime and CLI work easier to land safely.

## Upgrade

```bash
vilano update
vilano version
```
